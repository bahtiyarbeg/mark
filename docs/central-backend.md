# Централизованный GET AI MARKETING

Все 18 существующих направлений сохранены. `GET /api/orchestrator` возвращает реестр и статусы исполнителей. `POST /api/orchestrator` принимает `{action,input}` и возвращает ID запуска, время, статус, провайдера, ограничения и результат. Старые API сохранены для совместимости; помощник и веб-проверки интерфейса используют общий оркестратор. CRM не затронута.

## Как пользоваться

1. Откройте **Подключения**. Введите название, HTTPS-ссылку и назначение (свой аккаунт или конкурент). Нажмите **Сохранить и проверить**.
2. Telegram: публичная ссылка `https://t.me/channel`. Читаются до 12 доступных сообщений из веб-просмотра; закрытые каналы, полная история, реакции и отправка сообщений не подключены.
3. TikTok: `https://www.tiktok.com/@name`. Instagram: `https://www.instagram.com/name/`. Ссылка сохраняется со статусом **Нужно подключить аккаунт**. OAuth и адаптеры этих платформ пока не реализованы. Добавление ссылки не даёт статистику или права публикации.
4. Для сайтов сохраняется снимок заголовка и description. При следующем запуске сравнивается отпечаток доступного содержимого. Это не полный crawl и не оценка продаж конкурента.
5. В **Все 18 AI-модулей** заполните название, факты или исходный текст. Нажмите модуль и **Выполнить**. Черновики и файлы доступны для скачивания.
6. **Проверка сайта** сохраняет прежние быстрый и подробный режимы. Подробный режим проверяет до 12 страниц gettravel.asia и предлагает исправления там, где хватает данных. Сайт автоматически не изменяется.

## Хранение и синхронизация

Ссылки, общий бриф и последние 30 запусков сохраняются в localStorage этого браузера и этого домена. Используйте резервную копию JSON. Импорт объединяет до 12 ссылок и повторно их проверяет; история из внешнего файла не считается серверным журналом. На другом устройстве данные автоматически не появятся. После очистки браузера данные могут быть потеряны.

Синхронизация выполняется по кнопке, а не по расписанию. Показаны отдельно последняя попытка и последний успешный снимок. Ошибка не заменяется выдуманными показателями. Общая облачная база, авторизация владельца и фоновый worker — отдельный следующий этап; без них нельзя обещать постоянный мониторинг.

## Локальный исполнитель

Нужен Node.js 22+. Запуск: `npm start`, адрес `http://127.0.0.1:3000`. Сервер слушает только loopback и отклоняет другой Host/Origin. Устанавливать зависимости Node для работы не требуется.

Для текста установите Ollama самостоятельно и выберите уже загруженную **локальную** модель. Перед запуском задайте `OLLAMA_MODEL` точным именем из `ollama list`. Сервер проверяет `/api/tags` на `127.0.0.1:11434`; облачные модели не выбираются, загрузки автоматически не запускаются. В панели выберите «Локальный AI». Переводы обязательно проверять человеком. [Ollama API](https://docs.ollama.com/api).

Для MP4 установите FFmpeg в PATH или укажите `FFMPEG_PATH` — полный путь к исполняемому файлу. При обнаружении FFmpeg в локальной панели появляется загрузка 1–8 JPEG/PNG до 5 МБ. Получается вертикальное слайд-шоу 720×1280, 5 секунд на фото, без звука. SRT скачивается отдельно; он не вшивается в MP4. Файлы остаются в `output/` на вашем компьютере. Локальный сервер не требует и не создаёт публичный туннель.

## Расходы, доступ и безопасность

Новые маршруты не вызывают платный AI. Существующий `/api/generate` сохранён с проверками `MARKETING_ACCESS_CODE` и `OPENAI_API_KEY`; он отдельно может расходовать баланс при явном вызове. Секреты не вводятся в пользовательские формы и не возвращаются в статусах.

На Vercel доступны ограниченные публичные операции. Используются обычные лимиты хостинга, а не обещание бесконечного бесплатного ресурса. Каждый запрос ограничен 100 КБ, 12 источниками; чтение источника ограничено по времени, размеру и редиректам. HTTPS-адреса проходят проверку DNS с закреплением публичного IPv4; локальные адреса и credentials в URL запрещены. Backend не сохраняет присланные ссылки в общей базе. Сохраняйте защиту проекта Vercel, не открывайте платные API без контроля доступа.
